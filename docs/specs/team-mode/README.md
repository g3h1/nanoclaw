# Team mode

## The idea

Make NanoClaw work like an agency. The agent the human talks to acts as a **lead** — it triages the request, dispatches to **specialist roles** (researcher, planner, builder, writer, reviewer, …), often in parallel, then merges the results and replies once.

Today, the agent answering on a channel is a single generalist. There is no curated specialist roster, no triage step, no built-in coordinator pattern. Team mode adds that layer on top of the existing entity model — the agent group is still the agent's identity; team mode is a way of operating.

## Why

The user wants better outcomes on substantive tasks (research, building, multi-step work) without manually orchestrating helpers. A lead-with-specialists pattern produces stronger answers than a single generalist for tasks that benefit from division of labor and an internal critic.

## Out of scope for the idea (capture only)

Implementation shape, where specialists live (SDK subagents vs peer agent groups), the initial roster, dispatch heuristics, telemetry, UI surface — all deferred until the user wants to plan.
